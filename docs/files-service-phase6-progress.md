**Contract facts gathered before starting** (so subsequent sessions don't re-derive):
- `POST /certificates` body: `{ name, format, certificateAssetId, keyAssetId?, passPhrase? }`; `format` round-trips as `"Pfx"|"Pem"` (`Enum.ToString()`), not `"PFX"|"PEM"`.
- `CertificateDto`: `id, name, format, certificateAssetId, keyAssetId?, certificateFileName, keyFileName?, subject, subjectAlternativeNames[], notBefore, notAfter, thumbprint, createdAt, updatedAt`. No `friendlyName`/`uploadedAt`/`hasPassphrase` — those were mock-only fields.
- Files `POST /files?assetType=certificate` (multipart, one file per call) → 201 `FileAssetDto { id, assetType, fileName, contentType, sizeBytes, sha256, status, ownerType?, ownerId?, uploadedBy, createdAt, committedAt? }`, `Staged`. Commit happens server-side inside `CreateCertificateHandler` — **UI never calls `/files/{id}/commit` directly**, only uploads then posts to `/certificates`.
- `apiFetch` in `lib/proxy-manager-client.ts` hardcodes `Content-Type: application/json` — breaks multipart boundary; needs a second fetch helper that omits it.
- BFF (`app/api/**`) calls `PROXY_MANAGER_API_URL` directly (server-to-server, bypasses YARP) — Files needs its own `PROXY_MANAGER_FILES_URL` env var for the same reason (dev default `http://localhost:5002`, matching the port picked in Phase 5).
- `ProxyHost.certificate` is currently typed `ProxyCertificate { certificatePath, keyPath }` (dead/mock) — plan issue #8 says change to `certificateId?: string`.
